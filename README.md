# 💀 Чёрный Вестник

Самостоятельный Telegram-бот: каждый вечер он делает из переписки группы едкую сатирическую газету с матом. Без платной подписки, без своего постоянно работающего сервера, с опорой на реальные сообщения и возможностью отказаться от сбора данных.

**Версия:** MVP 0.2.2 (21 октября 2026). **Статус:** Telegram-бот развёрнут в Cloudflare, база D1 создана, реальный ответ Groq получен, Telegram webhook зарегистрирован и проверен независимым smoke-тестом. **В группу ещё не добавлен; реальные групповые публикации и следующий Cron пока не проверены.** Подробнее см. [ACCEPTANCE.md](ACCEPTANCE.md).

## Быстрый запуск без компьютера через GitHub Actions

Основной репозиторий: https://github.com/xxiamadelxx-blip/cherny-vestnik-

1. Создайте Telegram-бота у [@BotFather](https://t.me/BotFather) (`/newbot`); отключите ему Privacy Mode (`/setprivacy` → Disable). Токен никому не отправляйте.
2. Зарегистрируйте бесплатные Cloudflare и Groq аккаунты. Получите [Cloudflare API Token](https://dash.cloudflare.com/profile/api-tokens) с разрешениями Workers Scripts Edit и D1 Edit, [Cloudflare Account ID](https://dash.cloudflare.com/) и [Groq API key](https://console.groq.com/keys).
3. Откройте **GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret**. Создайте **четыре** секрета:
   - `CLOUDFLARE_API_TOKEN` (API Token Cloudflare)
   - `CLOUDFLARE_ACCOUNT_ID` (Account ID Cloudflare)
   - `TELEGRAM_BOT_TOKEN` (токен от BotFather)
   - `GROQ_API_KEY` (API key Groq)
4. Откройте [Actions → Deploy Telegram bot on Cloudflare Free](https://github.com/xxiamadelxx-blip/cherny-vestnik-/actions/workflows/deploy.yml) → **Run workflow**. Скрипты автоматически находят/создают D1, применяют SQL, публикуют Worker, задают Worker Secrets и регистрируют Telegram webhook. Секрет webhook генерируется автоматически на каждом развёртывании и не хранится в GitHub.
5. Добавьте бота в группу, предупредите участников о том, что сообщения будут кратковременно сохраняться и отправляться в Groq; затем от имени администратора выполните `/enable` и `/now` после пары сообщений.

Проверка реального запуска: последняя стадия workflow должна отчитаться `Bot deployed and webhook registered` с `workers.dev` URL; далее в Telegram проверяется `/status`, затем публикация `/now`. **Без четырёх GitHub Secrets автоматическое развёртывание не запустится.** Пароли, токены и содержимое переписки нельзя публиковать в репозитории.

**Права бота**: в группе нужны получение новых сообщений и возможность отвечать. Privacy Mode отключается через BotFather. Само наличие кода в GitHub не означает, что бот работает в Telegram.

### Запуск вручную

В случае ограничений GitHub Actions можно выполнить `npm install`, `node scripts/provision-d1.mjs`, `npx wrangler d1 migrations apply cherny-vestnik --remote --yes`, `npx wrangler deploy` и `node scripts/activate-cloudflare.mjs` в GitHub Codespaces с теми же переменными окружения. Другая настройка конфигурации D1 UUID не требуется.

## Что уже работает в коде

- Сбор **новых** сообщений Telegram group/supergroup через подписанный секретом webhook. Сообщения до добавления бота восстановить нельзя.
- Команды администратора `/enable`, `/disable`, `/time HH:MM`, `/now`, `/status`, `/wipe`, `/help`.
- `/forgetme` любого участника удаляет его хранимые сообщения, очищает память бота и отключает сбор его **будущих** сообщений; `/optin` включает их сбор снова.
- Приём только после `/enable` администратором; чужие приватные, пересланные сообщения и сообщения ботов игнорируются.
- Дневная публикация по часовому поясу `Europe/Moscow` (по умолчанию 21:00), Cron каждую минуту, one-per-day блокировка в D1.
- Ускоренная генерация **несколькими** запросами к Groq Qwen3.8-27b в пределах типичного бесплатного лимита.
- Полная поэтапная обработка **каждого сохранённого текстового сообщения** из закрытого суточного окна, включая 300 и 1000 сообщений. Промежуточные факты и ID сохраняются в D1; Cron каждую минуту продолжает незавершённый анализ. Финальная газета опирается на краткие сводки **всех** обработанных порций, а не на выборку 85 сообщений. При недостатке Groq-квоты выпуск откладывается, а не выдаётся за полный.
- Отсылки к двум предыдущим выпускам для продолжения локальных мемов, без выдачи их за свежие факты.
- Аварийный статистический выпуск, если AI недоступен, без выдуманных диалогов.
- Разделение длинного отчёта на Telegram-сообщения менее 3800 символов, сохранение прогресса отправки для повторной попытки.
- Очистка исходных сообщений через 4 дня, памяти шуток через 14 дней; `/wipe` удаляет всё из базы выбранной группы.
- При изменении согласия или выключении бота во время генерации публикация отменяется.

## Архитектура

`Telegram group` → `webhook` → `Cloudflare Worker` → `D1` → `Cron 1m` → `Groq evidence extraction in consecutive batches` → `D1 batch ledger` → `final synthesis` → `Telegram sendMessage`.

Скрипт JavaScript ESM без runtime-зависимостей, база D1 (SQLite), тесты Node.js 22 с встроенным `node:sqlite`. Не нужен ПК, Docker или собственный VPS. Проект рассчитан на одну/несколько небольших групп, а не на массовый коммерческий сервис.

## Руководство по развёртыванию

Для автоматического запуска используйте раздел «Быстрый запуск» выше. Он заменяет старую ручную процедуру Cloudflare D1 + webhook. Новые запуски в GitHub Actions повторно используют существующую базу D1, не сбрасывая сохранённую переписку.

## Как запустить автоматизированные тесты

```bash
npm run check
npm test
npm run test:coverage
```

Тесты используют встроенную SQLite в Node.js 22. **Реальные Telegram getMe, Groq completion, Cloudflare D1/Worker и webhook уже проверены в GitHub Actions.** Реальный сценарий публикации в группе остаётся не подтверждён. Для производственной приёмки нужно отдельно пройти реальные проверки `/enable` → новые сообщения → `/now` → следующий день Cron → `/forgetme`.

## Разумные границы токсичности

По умолчанию стиль максимально матерный. В промпте разрешены жёсткие прозвища и прожарка **поступков участников**, но запрещены выдуманные факты, угрозы, разглашение данных, ненависть по защищённым признакам и систематическая травля одного участника. Это сознательное отличие от полностью бесконтрольного бота. Можно менять промпт в `src/ai.js`.

Любое сообщение группы является **недоверенными входными данными**, а не инструкцией модели. При недостатке контекста бот обязан избегать ложной уверенности. Выдуманные ссылки вида `[#123]` заменяются на `[без подтверждения]`. Это не абсолютная защита от всех галлюцинаций: приёмка требует проверки вручную.

## Ограничения бесплатных тарифов

На дату подготовки (октябрь 2026): Cloudflare Workers Free: до 100 тыс. запросов/сутки; D1 Free: 5 млн прочитанных строк и 100 тыс. записанных строк/сутки, 5 ГБ хранения. Groq Qwen3.8-27B Free: 1000 запросов и 200 тыс. токенов/сутки, с поминутными лимитами. **0 ₽ возможно только внутри этих квот**. При превышении Worker/D1 перестанут обслуживать запросы до сброса лимита; бот не должен молча переключаться на платные тарифы.

Документация: [Telegram Bot API](https://core.telegram.org/bots/api), [Cloudflare Workers](https://developers.cloudflare.com/workers/platform/limits/), [D1](https://developers.cloudflare.com/d1/platform/pricing/), [Groq rate limits](https://console.groq.com/docs/rate-limits), [Groq API](https://console.groq.com/docs/api-reference).

## Инженерные оговорки / следующие доработки

- Telegram может повторить webhook; входные сообщения дедуплицируются по `(chat_id,message_id)`. При сбое **после успешной Telegram-отправки, но до отметки в D1** возможен повтор части выпуска: гарантия exactly-once через Telegram Bot API в общем случае недостижима. Нормальный повтор Cron не создаёт дублей.
- Для 1000+ сообщений бот использует порционную, возобновляемую обработку без выборки и без лимита в 2000 сообщений. Если бесплатные квоты модели исчерпаны, выпуск задерживается, но не объявляется полным с пропусками.
- Система не распознаёт смысл голосовых, картинок и видео; только текст и подписи.
- Исходный текст (включая имена и выдержки) отправляется в Groq. Не используйте для секретных/закрытых чатов без согласия участников.
- Время публикации Москва по умолчанию. Другой `BOT_TIME_ZONE` через `wrangler.jsonc`; команда `/time` задаёт часы и минуты для этого часового пояса.

## Изменения v0.2: полный охват и более жёсткая прожарка

Вместо прежней выборки 85 сообщений Worker анализирует сохранённый текст последовательными порциями (до 40 сообщений, ограничение по символам на порцию). После успешного Groq-анализа каждая порция и её реальные Telegram message ID фиксируются в таблице `digest_chunks` базы D1. В следующую минуту Worker продолжает со следующей порции. Финальный выпуск формируется **только когда обработано 100%** записанных сообщений за зафиксированный период.

Если Groq отвечает 429, публикация **не** подменяется статистической заглушкой: повторный Cron продолжает после восстановления квоты. Большой чат может получить выпуск **позже установленного часа**, если бесплатные токены/запросы заканчиваются. Это принципиальное условие честного полного охвата. В выпуске из 1000 сообщений не обязательно будут упомянуты все реплики, но все они проходят в модель на этапе анализа. Входной текст одного сообщения сохраняется до 4096 символов; медиа/голосовые без текста по-прежнему не расшифровываются.

Редактор требует острой, матерной прожарки конкретных слов и действий, без выдуманных преступлений, травли, угроз и унижений по уязвимым признакам. Следует проверять точность пересказов и авторство цитат: корректный ID сам по себе не доказывает достоверности формулировки.

Автоматизированная проверка охвата 1000 сообщений: `tests/exhaustive.test.js`. Настоящий Groq на 300 сообщениях: `reports/simulation-300.md`. Реальный прогон 1000 сообщений завершён (1000/1000; 25 порций, 28 вызовов Groq): [результат](reports/simulation-1000.md). Workflow остаётся доступным для ручного повторения и сохраняет артефакт.

## Автоматическое соблюдение бесплатных лимитов Groq (v0.2.1)

- Миграция `migrations/0003_groq_budget.sql` создаёт общую таблицу `groq_budget` в Cloudflare D1, а `migrations/0004_digest_reductions.sql` добавляет кеш промежуточных сводок. В ней хранятся **только счётчики**, время сброса квот и код ошибки. Текст переписки и токен доступа туда не записываются.
- Перед каждым обращением к Groq Worker сверяет доступность квоты. Ответы Groq читаются по официальным заголовкам `x-ratelimit-remaining-tokens` (остаток токенов **в минуту**) и `x-ratelimit-remaining-requests` (остаток запросов **за сутки**), а также времени их сброса.
- При `HTTP 429` бот уважает `retry-after` (секунды или HTTP-дата). Если известен точный сброс минутного либо суточного лимита, ждёт не меньше него. При отсутствии заголовков применяет увеличивающиеся паузы.
- **Не требуется sleep в Cloudflare Worker.** Состояние сохраняется в D1, и ежеминутный Cron продолжает работу, когда пауза истечёт. Перезапуск сервера не отменяет ожидание.
- Обработанные части сохраняются в `digest_chunks`, а промежуточные сводки редактора в `digest_reductions` с SHA-256 хэшем входного текста. После лимита/обрыва удачно завершённые этапы не генерируются повторно. При исчерпании квоты газета **не публикуется частично**; повторный запуск продолжает с первого необработанного этапа.
- Мягкий суточный бюджет проекта по умолчанию `GROQ_DAILY_TOKEN_SOFT_LIMIT=180000` токенов, с запасом относительно бесплатных 200000. Порог остатка минутных токенов `GROQ_TOKEN_RESERVE=3500`. Это **консервативный учёт только расходов бота**, а не точный остаток всех приложений в организации Groq. При отсутствии поля `usage.total_tokens` точный локальный расход определить нельзя; окончательное ограничение задаёт сам Groq.
- Команда `/status` показывает время ближайшего разрешённого запроса по Москве, локальный счётчик токенов и прогресс `обработано/всего`.
- Никакого автоматического перехода на платные ключи и никакой покупки дополнительных квот нет.
- Автоматический деплой проверяет доступность модели через `GET /models`, **не запрашивая платёжно-токенную генерацию**. Реальные тесты на 300/1000 сообщений и полный preflight запускаются отдельно вручную через GitHub Actions, чтобы не сжигать бесплатную квоту на каждом коммите.

**Ограничение:** если одновременно в Groq работают другие приложения с тем же организационным лимитом, они могут расходовать квоту помимо счётчиков бота. В таком случае Groq вернёт `429`, и бот восстановит ожидание по заголовкам сервера. Полная точность анализа фактов и реальная доставка газеты в Telegram-группу по-прежнему требуют отдельной приёмки.

Источник полей: [официальная документация Groq Rate Limits](https://console.groq.com/docs/rate-limits).

## Редакторский фактчекинг v0.2.2

- Перед отправкой газеты проверяются все явно указанные `[#ID]`: каждое должно принадлежать сохранённому сообщению именно этой группы.
- Дословные цитаты рядом с `[#ID]` сверяются с реальным текстом сообщения. Ложную цитату или неизвестный ID нельзя провести в Telegram просто красивой подачей.
- При небольшой грамматической разнице программа может **без ИИ** заменить фрагмент на реальную непрерывную цитату из указанного сообщения. Она никогда не придумывает новую цитату. Если совпадение недостаточно уверенное, публикация блокируется.
- Явный пропуск внутренней буквы в имени исправляется только рядом с подтверждающим `[#ID]`, без изменения текста прямой цитаты. Дата на первой строке газеты всегда подставляется из дня выпуска в D1.
- Более серьёзную ошибку бот один раз пытается исправить через Groq, предоставляя только сообщения, которые сам черновик цитировал; затем проверяет результат повторно.
- Непринятый черновик сохраняется в `digests.editorial_draft` (миграция `0005_editorial_drafts.sql`), поэтому при 429 во время исправления первоначальная генерация не повторяется. При повторной ошибке редактура ждёт 15 минут, не выжигая квоту ежеминутными попытками.
- `/forgetme`, `/disable`, `/wipe` и смена согласия стирают соответствующие незавершённые сводки; сохранённые сообщения не передаются новой редактуре после отзыва разрешения.
- Сквозные тесты используют вымышленную переписку и изолированный Telegram. Публикация в настоящую группу по-прежнему не проверена.

**Важная граница проверки:** точный номер сообщения и дословная цитата не доказывают истинность всех выводов, метафор и мотивов участников. Семантическую достоверность и качество персональной прожарки следует принимать отдельно, сопоставляя текст с исходными сообщениями.

Реальный малый редакторский прогон: [GitHub Actions](https://github.com/xxiamadelxx-blip/cherny-vestnik-/actions/workflows/editorial-live.yml). Итоги и статус PASS/FAIL находятся в `ACCEPTANCE.md`.
